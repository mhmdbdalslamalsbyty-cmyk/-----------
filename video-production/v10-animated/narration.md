# V10 — الاستدعاء الذاتي: عندما تصغّر المشكلة

**المواصفة:** رسوم تعليمية ثنائية الأبعاد، 16:9، خلفية داكنة متسقة مع هوية الأكاديمية، عربية فصحى محايدة، بلا موسيقى.

| المشهد | عنوان المشهد | النص المنطوق |
|---|---|---|
| 01 | سؤال البداية | الاستدعاء الذاتي ليس تكرارًا غامضًا للدالة. إنه أسلوب يحل فيه البرنامج نسخة أصغر من المشكلة نفسها. لكن لكي يتوقف بأمان، نحتاج دائمًا إلى حالة أساس واضحة. |
| 02 | المشكلة تصغر | لنحسب عدًا تنازليًا من ثلاثة. الدالة count تستدعي count للعدد الأصغر: من ثلاثة إلى اثنين، ثم إلى واحد. كل نداء جديد يحمل مهمة أصغر من المهمة السابقة. |
| 03 | بطاقات النداء | تخيل أن كل استدعاء يضع بطاقة على مكدس النداءات. تظهر count ثلاثة في الأسفل، وفوقها count اثنان، ثم count واحد. لا تنفذ البطاقات العليا نهايتها قبل أن ينتهي ما استدعتْه. |
| 04 | حالة الأساس | عندما يصل العدد إلى صفر، لا ننشئ بطاقة جديدة. هذه هي Base Case. إنها الجواب البسيط الذي يوقف السلسلة ويمنع الدالة من استدعاء نفسها بلا نهاية. |
| 05 | لحظة العودة | بعد Base Case تبدأ البطاقات بالعودة بالعكس. تنتهي count واحد، ثم تستأنف count اثنان، ثم count ثلاثة. لهذا يبدو الاستدعاء الذاتي كرحلة إلى الداخل ثم طريق عودة. |
| 06 | ترتيب التنفيذ | لا تخلط بين ترتيب النداءات وترتيب الطباعة. إذا طبعت قبل الاستدعاء سترى الأعداد أثناء النزول، وإذا طبعت بعده تراها عند العودة. موضع سطر واحد يغير القصة التي يعرضها البرنامج. |
| 07 | قاعدة الأمان | كل استدعاء ذاتي جيد يجيب عن سؤالين: ما المشكلة الأصغر؟ وما شرط التوقف؟ إن غاب أحدهما، قد يكبر Call Stack بدل أن يفرغ، وينتهي بخطأ لا نريده. |
| 08 | الخلاصة | Recursion يعني: صغّر المشكلة، اقترب من Base Case، ثم دع النتائج تعود عبر Call Stack. ابدأ بمثال صغير تستطيع تتبع بطاقاته، قبل استخدام الفكرة في أشجار أو مسائل أكبر. |
