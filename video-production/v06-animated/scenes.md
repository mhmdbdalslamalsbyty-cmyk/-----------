# V06 — المكدس بالمصفوفة: آخر داخل، أول خارج

## نظرة عامة

| الحقل | القرار |
|---|---|
| الموضوع | مكدس قائم على مصفوفة: `top` وPush وPop وPeek وحدود Underflow وOverflow |
| الجمهور | مبتدئ يعرف المتغيرات والدوال والحلقات في Java |
| الخطاف | لماذا تشبه ميزة التراجع كومة أطباق؟ |
| الإطار | 16:9، 1920×1080، 60fps، ManimCE 2D |
| الهوية | خلفية كحلية داكنة، فيروزي للقيمة/القمة، مرجاني للتحذير، نص عربي مختصر عالي التباين |
| الصوت | 8 ملفات WAV عربية فصحى، صوت Charon، بلا موسيقى |
| المدة الصوتية المقاسة | 149.16 ثانية؛ ستتوقف الحركة عند عقود الصوت لا عند تقديرات النص |
| محرك الرسم | ManimCE core mobjects فقط؛ لا توجد حاجة فعلية إلى إضافة خارجية لأن الخانات والأطباق والمؤشر مكونات هندسية بسيطة قابلة للضبط الدقيق |

## القوس السردي

يبدأ الشرح بكومة أطباق ملموسة ثم يحولها تدريجيًا إلى مصفوفة ذات مؤشر `top`. تتتابع العمليات على البنية نفسها حتى يصبح ترتيب LIFO واضحًا بصريًا، ثم تعرض الحالات الحدّية بوضوح مرجاني، وتنتهي بسؤال يميز Peek من Pop.

## ملاحظات تنفيذية

تستعمل كل مشاهد `wait_until`/تعويضات زمنية محسوبة داخل `pace()` محليًا بحيث تساوي مدة الفيديو مدة WAV للمشهد ضمن أقل من نصف ثانية. تُرسم الكلمات العربية ككتل نصية قصيرة لا كفقرات، وتبقى رموز Java والإنجليزية LTR منفصلة مكانيًا عن العربية. لا تُستخدم ملفات مرئية خارجية ولا موسيقى ولا `MathTex`.

## القبول قبل الربط

1. ينجح العرض المنخفض لجميع المشاهد.
2. تراجع إطارات تمثيلية لضمان وضوح القمة والخانات والحدود.
3. يكون الفرق الكلي بين الحركة والصوت ≤1 ثانية، وفرق كل مشهد ≤0.5 ثانية.
4. يصدر MP4 حقيقي H.264/AAC ثم يتحقق `ffprobe` وHTTP Range قبل لمس كتالوج الدرس.
